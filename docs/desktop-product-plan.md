# AgentGlow 桌面应用产品规划

本文是 P6 Desktop 的产品基线。技术边界以《AgentGlow 技术规划》为准，实施顺序以
《AgentGlow 开发路线图》为准；当旧讨论与本文冲突时，以本文记录的首版范围为准。

## 1. 产品原则

1. 整体结构参考 VoxSpell：左侧切换功能分类，右侧展示当前页面。
2. 应用内部配置修改即生效，不提供手动保存。
3. 硬件界面由设备注册信息生成，不按已知设备类型写死。
4. 服务运行和开机启动由一个总开关统一管理。
5. 灯光配置只提供恢复默认，不建设预设系统。
6. Agent 集成支持 Codex、OpenCode 和 ZCode。
7. 界面使用用户能理解的任务和设备语言，不暴露 daemon 内部状态机概念。

## 2. 信息架构

桌面主窗口使用 `AdwNavigationSplitView`：

| 左侧页面   | 右侧主要内容                                             |
| ---------- | -------------------------------------------------------- |
| 概览       | 服务总开关、当前活动、设备与错误摘要、运行诊断与脱敏导出 |
| 灯光样式   | 各任务阶段的颜色、动画、亮度和时间参数                   |
| 设备       | 注册驱动的设备信息、独立启用项和动态配置表单             |
| Agent 集成 | Codex、OpenCode、ZCode 的检测、安装和移除                |
| 关于       | 版本、项目说明、许可证和链接                             |

宽窗口同时展示导航与内容，窄窗口采用 libadwaita 的标准折叠导航。首版不增加仪表盘、
系统托盘或额外导航层级。

## 3. 概览与服务总开关

概览页顶部只出现一个 AgentGlow 总开关：

- 开启：执行用户服务的 `enable --now`，结果成功后显示开启；
- 关闭：执行用户服务的 `disable --now`，daemon 停止前恢复设备，成功后显示关闭；
- 操作中禁用重复点击并显示进度；
- 操作失败时回到系统真实状态并展示可执行的错误信息；
- 若运行状态与开机启动状态意外不一致，不制造第二个开关，只提示诊断并允许用户用总开关收敛状态。

其余内容只回答“现在是否有活动任务、灯光正在表达什么、设备是否正常”。内部状态名、
租约、恢复快照等实现细节不作为界面内容。

## 4. 灯光样式

样式页编辑任务阶段对应的：

- 先选择动画类型，再配置该动画适用的颜色和参数；
- 静态动画使用一个 GTK 原生拾色器，呼吸、数据流和脉冲分别配置起始、终止颜色；
- 动画类型；
- 亮度或强度范围；
- 周期、持续时间、最短展示时间和全局过渡时间；
- 成功、失败与暂停状态的最长保持时间；
- 设备声明可用时的原生效果参数。

交互规则：

1. 表单输入先在本地更新，再经过约 200–300 ms 节流提交完整配置。
2. 连续修改采用 latest-wins，较早请求返回时不得覆盖较新的输入。
3. daemon 完整校验并原子保存；成功后硬件立即采用新配置。
4. 提交失败时保留用户输入、定位具体字段，并让运行态继续使用最后一次成功配置。
5. 页面没有“保存”按钮，也没有内置或自定义预设。
6. “恢复默认”先明确影响范围，确认后恢复项目默认参数并立即应用。

## 5. 独立预览窗口

点击预览后打开独立窗口，而不是在设置页内播放：

- 显示当前预览阶段的用户可读名称和简短提示；
- 背景或主视觉实时呈现对应颜色、亮度变化和动画节奏；
- 自动按顺序循环全部用户可配置阶段，不提供手动阶段选择；
- 阶段文字保留并增加描边，确保在不同预览颜色下清晰可读；
- 设置页的连续输入即时更新预览目标；
- 预览窗口消费 daemon 输出的有限频率渲染帧，不在 Desktop 复制灯光动画算法；
- 关闭窗口、Desktop 断开或 TTL 到期都会调用或等价触发 `preview.stop`，恢复正常灯光。

预览窗口只承担视觉核对，不承载配置表单。

## 6. 注册驱动的设备页

设备注册契约使用 TypeBox 作为唯一结构和运行时校验来源。每个设备至少注册：

- 稳定设备 ID、显示名称、可选说明和健康状态；
- 能力与当前降级信息；
- 配置字段的 key、标签、说明、控件类型、约束、默认值和顺序；
- 字段是否按任务阶段重复；
- 设备独立启用项，默认值为 `true`。

首版通用表单至少支持布尔开关、枚举、数值范围和只读信息。后续硬件需要新控件时，
先扩展注册 schema、协议和通用渲染器，再由设备声明使用。Desktop 不允许出现
`if Aura`、`if Slash` 或按 backend 名称选择页面的逻辑。

设备配置同样自动生效，并复用样式页的节流、latest-wins、字段错误和最后成功配置策略。

## 7. Agent 集成

当前实现 Codex、OpenCode 和 ZCode，三者分别维护真实 Hook schema、fixtures 和安装模板。
集成页可以自动检测，但修改 Agent 的外部配置必须：

1. 展示目标文件；
2. 展示修改前后的 diff；
3. 等待用户明确确认；
4. 原子写入，并支持幂等升级和移除。

这里的确认只针对外部 Agent 配置，不改变应用内部配置即时生效的规则。首版不显示未支持
Agent 的占位卡片。

## 8. Desktop 与 daemon 边界

Desktop 只负责展示、收集输入和发起 RPC。以下能力必须留在 daemon：

- 配置校验、持久化和运行态切换；
- 服务之外的业务真相；
- 状态仲裁、动画与逐帧计算；
- backend、D-Bus 和硬件访问；
- 设备注册聚合；
- 预览 TTL 与异常恢复。

Desktop 断开或崩溃不得影响 daemon 的正常灯效；任何未显式停止的预览都必须由 TTL
兜底回收。

## 9. P6 交付切片

| 切片 | 交付结果                       | 验收重点                             |
| ---- | ------------------------------ | ------------------------------------ |
| P6-A | 可构建、可测试、可启动的空窗口 | `yarn tiny desktop` 可打开窗口       |
| P6-B | 双栏框架与五页导航             | 宽窄窗口导航均可用                   |
| P6-C | 概览与单一服务总开关           | 开启和关闭分别收敛运行与开机状态     |
| P6-D | 自动生效的灯光样式页           | 无保存按钮，错误不破坏最后成功运行态 |
| P6-E | 独立预览窗口                   | 阶段提示和视觉实时同步，关闭后恢复   |
| P6-F | 注册驱动设备页                 | 新设备只需注册字段，无需修改页面分支 |
| P6-G | Agent 和关于页                 | 诊断并入概览；外部写入有 diff 和确认 |

P6 完成后再进入 P7 的真实 Hook 安装和日常使用验证。首版优先完成闭环，不增加 CI、
预设系统、Claude Code、第二个生产 backend 或与 MVP 无关的设置项。

截至 2026-07-26，P6 全部切片和 P7 安装器软件实现已经完成。`yarn tiny desktop`
是当前完整功能验收入口；打包、desktop entry 和发行安装仍属于 P8，不在本阶段处理。
